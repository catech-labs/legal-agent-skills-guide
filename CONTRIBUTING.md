# Contributing

Contributions are welcome when they improve factual accuracy, evaluation quality, or coverage.

## Suggesting a project

Open an issue using the project suggestion template and provide:

- canonical repository URL;
- project owner;
- legal workflows covered;
- jurisdictions;
- supported agents or runtimes;
- license;
- installation method;
- executable components;
- data and connector requirements;
- maintenance evidence;
- known limitations;
- date reviewed.

## Inclusion criteria

A project must have:

- a public repository;
- a clear legal workflow purpose;
- identifiable maintainers;
- usable documentation;
- visible licensing information;
- enough information for independent evaluation.

## Review principles

- Do not rank projects only by stars.
- Do not describe a project as safe, verified, certified, or production-ready without published evidence.
- Separate upstream claims from independent findings.
- Prefer stable facts over volatile metrics.
- Record the review date.
- Link to the original repository.
- Do not copy third-party skills into this repository.

## Pull requests

Keep changes focused. Update both `README.md` and `README.pt-BR.md` when a recommendation materially changes. Update `catalog/projects.yml` for structured metadata.
